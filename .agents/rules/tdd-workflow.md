# AI-TDD Workflow Rules

AIを用いたテスト駆動開発（AI-TDD）において、品質を担保するための規則です。

## 1. Red（テスト失敗）先行の原則

実装のコードを書く前に、必ず失敗するテストケースを記述してください。
テストは仕様を最も明確に表現するプロンプトとして機能します。

## 2. 最重要アンチパターン：テストの改竄禁止

エージェントが実装をテストに通す際に、実装の修正ではなく「テストファイル側を書き換えて無理やりテストを通す」行為は厳禁です。

- **ルール**: 実装フェーズ（Greenへの反復）に入ったエージェントは、**対象のテストファイルを絶対に書き換えてはなりません**。
- 例外: 仕様変更によるテスト更新が明示的に指示された場合のみ。

## 3. R3F / Three.js 特有のテスト戦略

- 視覚的なピクセルマッチより、まずは `@react-three/test-renderer` を用いたシーングラフ・コンポーネントツリーの構造的テストを優先してください。
- 物理演算や `useFrame` に依存する時間の絡むテストは、時間のモック化（Mocker）を適切に設定してください。
